## 2. 先明确 PF 的四段闭环

`677099a` 里的 native PF 不是单个函数，而是一个每 TTI 闭环：

1. 先算 SINR
   - 生成 `postEqSinr`
   - 再聚合成 `wbSinr`
2. 再做 PF UE 选择
   - 用 `wbSinr` 和 `avgRatesActUe`
   - 产出 `setSchdUePerCellTTI`
3. 再做 PF PRG/PRB 调度
   - 用被选中 UE 的信道和 `avgRates`
   - 产出 `allocSol`
4. 最后做平均速率更新
   - 更新 `avgRates`
   - 再同步回 `avgRatesActUe`
   - 下一 TTI 再继续用

所以，PF 的“状态核心”其实是两个平均速率数组：

- `avgRates`
  - 选中 UE 视角
  - `cuMAC/src/api.h:98`
- `avgRatesActUe`
  - 全 active UE 视角
  - `cuMAC/src/api.h:105`

## 5. UE 选择阶段的原始 PF 实现

### 5.1 最值得先读的 CPU 参考实现

文件：`cuMAC/src/4T4R/multiCellUeSelectionCpu.cpp`

- `void cumac::multiCellUeSelectionCpu::setup(...)`
  - 行号：`152`
- `void cumac::multiCellUeSelectionCpu::run()`
  - 行号：`189`
- `void cumac::multiCellUeSelectionCpu::multiCellUeSelCpu()`
  - 行号：`32`

这个函数就是最直观的原始 UE 选择 PF：

1. 按 cell 扫描所有 `cellAssocActUe == 1` 的 active UE
2. 用 `wbSinr` 估算该 UE 的瞬时宽带速率
3. 按 PF 指标排序
4. 取前 `numUeSchdPerCellTTI` 个，写入 `setSchdUePerCellTTI`

核心公式在这里：

```cpp
dataRate = sum_j W * log2(1 + wbSinr[uIdx * nUeAnt + j]);
pfMetric = pow(dataRate, betaCoeff) / avgRatesActUe[uIdx];
```

对应源码位置：

- `dataRate += pCpuDynDesc->W*log2(1.0 + pCpuDynDesc->wbSinr[...]);`
  - `multiCellUeSelectionCpu.cpp:49`
- `pfTemp.first = pow(dataRateF, pCpuDynDesc->betaCoeff)/pCpuDynDesc->avgRatesActUe[uIdx];`
  - `multiCellUeSelectionCpu.cpp:52`

额外逻辑：

- 若 `bufferSize[uIdx] == 0`，直接跳过
  - `multiCellUeSelectionCpu.cpp:41-43`
- 若 HARQ 重传，直接赋最大优先级
  - `pfTemp.first = std::numeric_limits<float>::max();`
  - `multiCellUeSelectionCpu.cpp:57-63`

## 6. UE downselect：从 active UE 视角切到 selected UE 视角

这是 PF 调用链里非常关键、也最容易忽略的一环。

文件：`cuMAC/examples/network.cu`

- `__global__ void cumac::ueDownSel4TrKernel(...)`
  - 行号：`3871`
- `void cumac::network::ueDownSelectCpu()`
  - 行号：`4019`
- `void cumac::network::ueDownSelectGpu()`
  - 行号：`4070`

这一步的作用不是做 PF 决策，而是做“数据投影”：

1. 用 `setSchdUePerCellTTI` 把 active UE 映射成 selected UE 序列
2. 把 active UE 级别的：
   - `avgRatesActUe`
   - `tbErrLastActUe`
   - `estH_fr_actUe`
   - `prdMat_actUe`
   - `detMat_actUe`
   - `sinVal_actUe`
   复制成 selected UE 视角的数据
3. 这样后续 PRG scheduler 就能直接基于 selected UE 下标运行

最关键的两行是：

- `avgRatesGpu[uIdx] = avgRatesActUeGpu[globalUeId];`
  - `network.cu:3933`
- `tbErrLast[uIdx] = tbErrLastActUe[globalUeId];`
  - `network.cu:3934`

也就是说：

- UE 选择阶段用的是 `avgRatesActUe`
- PRG 调度阶段用的是 downselect 之后的 `avgRates`

### 7.2 GPU 默认核心函数

文件：`cuMAC/src/4T4R/multiCellScheduler.cu`

- `void cumac::multiCellScheduler::setup(...)`
  - 行号：`5400`
- `void cumac::multiCellScheduler::run(cudaStream_t strm)`
  - 行号：`5739`
- `static __global__ __launch_bounds__ (1024, MinBlkPerSM_) void cumac::multiCellSchedulerKernel_noPrdMmseIrc(mcDynDescr_t* pDynDescr)`
  - 行号：`693`

这个 kernel 的 PF 逻辑是：

1. 对每个 `(cell, rbg)`，枚举该 cell 关联的 selected UE
2. 基于所有协同小区的同 PRG 干扰，构造干扰协方差矩阵 `C`
3. 做 MMSE-IRC，得到每层 `SINR`
4. 计算该 UE 在该 PRG 上的瞬时速率
5. 按 PF 指标 `rate^beta / avgRates[uIdx]` 取最大 UE
6. 写入 `allocSol[rbg, cell]`

最关键的源码位置：

- 每层瞬时速率累加：
  - `sinrTemp = W * log2(...)`
  - `multiCellScheduler.cu:950-954`
- PF 指标：
  - `pfMetric[realAssocUeIdxInBlk] = pow(pfMetric[realAssocUeIdxInBlk], pDynDescr->betaCoeff)/pDynDescr->avgRates[uIdx];`
  - `multiCellScheduler.cu:958`
- 最终选最大 PF metric UE：
  - `pDynDescr->allocSol[rbgIdx*pDynDescr->totNumCell + cIdx] = maxi;`
  - `multiCellScheduler.cu:984`

这里的速率实际上等价于：

```cpp
rate_prg = sum_layer W * log2(1 + SINR_layer)
pfMetric_prg = pow(rate_prg, betaCoeff) / avgRates[uIdx]
```

因为代码里先算：

- `sinrTemp = 1.0 / diag(DInvMat)`
- 再把 `postEqSinr = sinrTemp - 1.0`
- 而 `log2(sinrTemp)` 实际上就是 `log2(1 + postEqSinr)`

  - 文件：`cuMAC/src/4T4R/multiCellSchedulerCpu.cpp`

这些分支与默认 type-0 PF 的差别主要是：

- 默认 `type-0`
  - 每个 `(cell, PRG)` 独立挑 PF 最大 UE
- `type-1`
  - 先为每个 `(UE, PRG)` 计算 PF metric
  - 再做连续 PRG 区间分配
  - 所以会用到 `pfMetricArr` 和 `pfIdArr`

但无论哪条分支，PF 指标核心都没变：

```cpp
PF = (instantaneous_rate ^ betaCoeff) / long_term_avg_rate
```

## 11. 一句话定位“原始 PF”

如果只用一句话概括 `677099a` 里的原始 PF：

- UE 选择 PF 看 `multiCellUeSelectionCpu::multiCellUeSelCpu()` / `multiCellUeSelKernel()`
- PRG 调度 PF 看 `multiCellSchedulerCpu::multiCellSchedulerCpu_noPrdMmse()` / `multiCellSchedulerKernel_noPrdMmseIrc()`
- PF 闭环状态更新看 `network::updateDataRateUeSelCpu()`、`network::updateDataRateGpu()`、`network::updateDataRateAllActiveUeCpu()`、`network::updateDataRateAllActiveUeGpu()`

这三段合起来，才是 `677099a` 的完整 native PF 实现。
